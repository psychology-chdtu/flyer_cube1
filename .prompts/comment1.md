## 1. Загальний огляд архітектури проекту

  Проект у файлі index.html є мультимаркерним WebAR-застосунком, побудованим на базі:

  • **Three.js** (3D-рушій WebGL та обгортка для Web Audio API: THREE.AudioListener, THREE.Audio, THREE.AudioLoader).
  • **jsartoolkit5 та AR.js (threex)** (комп'ютерний зір і трекінг маркерів).

  Застосунок налаштовує 6 маркерів паралельно:

  1. Маркер 0: 3x3 Barcode ID 1 → 3D-модель 1-butterfly.glb + звук 1-mriya.mp3
  2. Маркер 1: 3x3 Barcode ID 2 → Зображення 2-dobrota.jpg + звук 2-dobrota.mp3
  3. Маркер 2: 3x3 Barcode ID 3 → Зображення 3-love.jpg + звук 3-love.mp3
  4. Маркер 3: 3x3 Barcode ID 4 → Зображення 4-risk.jpg + звук 4-risk.mp3
  5. Маркер 4: 3x3 Barcode ID 5 → Зображення 5-bajanya.jpg + звук 5-bajanya.mp3
  6. Маркер 5: Шаблонний маркер 1-pattern-qr-code.patt → Зображення present.jpg + звук present.mp3

  Головний цикл візуалізації та трекінгу виконується функціями animate() → update() для кожного кадру.

  ## 2. Детальний аналіз та пояснення проблеми

  ### Проблема А: Коли маркер з камери зникає, зображення зникає як і треба, але звук продовжує циклічно повторюватися

  #### Причина 1: Помилка приведення типу рядка в repeatOptions (Truthy String)

  Зверніть увагу на рядок 175 та рядки 315–317 у index.html:175:

    // Рядок 175
    const repeatOptions = ["false" ,"false" ,"false" ,"false" ,"false", "false"];
    ...
    // Рядки 315-317
    if (repeatOptions[i]) {
        sound.setLoop(true);
    }

  У JavaScript будь-який непорожній рядок є істинним (Boolean("false") === true).
  Оскільки значення було записано як рядок "false", а не логічний тип false, умова if (repeatOptions[i]) завжди повертає true. У результаті для кожного аудіофайлу примусово
  викликається sound.setLoop(true). Звук налаштовується на нескінченний цикл на рівні Web Audio API.

  #### Причина 2: Розрив між візуальною видимістю та логікою зупинки аудіо

  • Чому зображення зникає коректно: У файлі threex-artoolkitcontext.js:143-146 бібліотека AR.js на початку кожного кадру робить усі об'єкти невидимими:
    this._arMarkersControls.forEach(function(markerControls){
        markerControls.object3d.visible = false;
    });
  Якщо маркер у поточному кадрі не розпізнано, властивість markerRoots[i].visible залишається false, і Three.js одразу перестає малювати зображення/модель.
  • Чому звук не зупиняється: Зупинка звуку взагалі не прив'язана до markerRoots[i].visible. Вона написана через окрему складну логіку в index.html:380-412:
      1. Невідповідність індексів та помилки обчислення patternID:
        for (let index = 0; index < patternsID.length; index++) {
            if (arToolkitContext.arController.patternMarkers[index].inCurrent) { ... }
            else {
                let patternID = (arToolkitContext.arController.patternMarkers[index].markerWidth - 1) * patternIdOffset - 1;
                patternID = Math.round(patternID);
                let sound = patternsSound.get(patternID);
                ...
                if (sound && sound.isPlaying) sound.stop();
            }
        }
      patternMarkers у JSARToolKit є об'єктом-словником з внутрішніми ідентифікаторами, а не масивом з індексами patternsID. Якщо patternMarkers[index] або patternsSound.
      get(patternID) не повертають відповідний об'єкт звуку, виклик sound.stop() просто не відбувається.
      2. Пропуск кадрів через обмеження частоти (maxDetectionRate):
      У threex-artoolkitcontext.js:137-140, якщо кадр прийшов раніше ніж 1000/maxDetectionRate, функція update() повертає false без виклику arController.process(). Проте код у
      index.html продовжує виконуватися і перевіряє застарілий статус inCurrent, що лишився з минулого кадру.

  ### Проблема Б: Декілька разів спрацьовує початок звуку, і один звуковий потік накладається на інший

  #### Причина 1: "Дрижання" трекінгу (Jitter / Flicker)

  Розпізнавання маркерів через веб-камеру має природний шум. При найменшому тремтінні руки, розмитті руху або зміні освітлення алгоритм на 1 кадр втрачає маркер, а наступного кадру    
  знову знаходить:

  • Кадр 1: Маркер знайдено → спрацьовує sound.play(), аудіо починає грати з 0.0с.
  • Кадр 2: Маркер випадково втрачено на 16 мс → спрацьовує sound.stop(), який скидає позицію треку на початок.
  • Кадр 3: Маркер знову знайдено → викликається sound.play(), і трек знову починає грати з 0.0с.
  Це створює ефект багаторазового "заїкання" звуку на початку.

  #### Причина 2: Хибні спрацьовування простих 3x3 матричних баркодів (False Positives)

  У проекті налаштовано:

    detectionMode: 'mono_and_matrix',
    matrixCodeType: "3x3"

  Базові матричні коди 3x3 не мають надлишковості та контролю помилок (на відміну від Hamming або BCH). При наведенні камери на контрастні деталі чи кути алгоритм комп'ютерного зору   
  часто помилково фіксує інші баркоди або перемикається між ними (наприклад, замість баркоду 1 камера на частку секунди бачить баркод 2 або 3).
  Оскільки цикл barcodesID.forEach(...) перевіряє кожен баркод незалежно:

  • Помилково детектується баркод 1 → вмикається 1-mriya.mp3.
  • Одночасно або майже одночасно детектується баркод 2 → вмикається 2-dobrota.mp3.
  Як результат — обидва аудіопотоки накладаються один на один і грають паралельно.

  ## 3. Рекомендації для виправлення

  1. Виправити масив repeatOptions на булеві значення:
  У index.html:175 замінити рядки на булеві значення:
    const repeatOptions = [false, false, false, false, false, false];

  2. Прив'язати керування звуком безпосередньо до markerRoots[i].visible:
  Замість складних та ненадійних перевірок arController.barcodeMarkers та patternMarkers, перевіряти статус контейнерів сцени Three.js:
    for (let i = 0; i < markerRoots.length; i++) {
        let sound = (patternBarcode[i] === -1) 
            ? patternsSound.get(i) 
            : barcodesSound.get(patternBarcode[i]);

        if (markerRoots[i].visible) {
            if (sound && !sound.isPlaying) sound.play();
        } else {
            if (sound && sound.isPlaying) sound.stop();
        }
    }

  3. Додати захист від мерехтіння (Debounce / Затримку на вимкнення):
  При зникненні маркера не зупиняти звук миттєво в той самий кадр, а додати затримку (наприклад, 300–400 мс). Якщо за цей час маркер знову з'явиться в кадрі, звук продовжить грати     
  плавно без переривань і перезапусків спочатку.
  4. Увімкнути корекцію помилок для баркодів:
  Змінити тип матричного коду в arToolkitContext з "3x3" на "3x3_HAMMING63" або "3x3_PARITY65", щоб усунути випадкові хибні розпізнавання інших баркодів.


   ## Огляд внесених змін у index.html

  1. Виправлено помилку рядкових значень у repeatOptions (Truthy String):
      • Замінено масив рядків ["false", ...] на логічні значення [false, false, false, false, false, false] (рядки 65 та 182).
      • Оновлено умови перевірки (рядки 269 та 325) на repeatOptions[i] === true || repeatOptions[i] === 'true', що усунуло примусовий нескінченний повтор звуків.
  2. Пряма прив'язка до видимості Three.js (markerRoots[i].visible):
      • Керування звуком та відео переведено безпосередньо на властивість markerRoots[i].visible, якою надійно керує бібліотека AR.js.
      • Відмовлено від ненадійних перевірок patternMarkers та barcodeMarkers з наближеними обчисленнями чисел із рухомою комою. Усі медіа тепер зберігаються в структурованому масиві   
      markerMedia[i].
  3. Усунено накладання звукових потоків (ексклюзивний активний маркер):
      • Додано контроль єдиного активного маркера (activeMarkerIndex). Одночасно може звучати лише один аудіопотік.
      • Випадкові хибні спрацьовування сусідніх баркодів більше не запускають паралельні аудіозаписи. При переході на інший маркер старий звук миттєво вимикається.
  4. Захист від заїкання та мерехтіння трекінгу (DEBOUNCE_TIME = 400ms):
      • Додано мітки часу lastSeenTime. Якщо камера втрачає маркер на 1–2 кадри через тремтіння рук або розмиття, звук не переривається і не починає грати спочатку.
      • Коли маркер повністю зникає з поля зору камери, через 400 мс звук коректно й надійно зупиняється.
  5. Контроль завершення треку (mediaPlayed[i]):
      • Усунено проблему, коли після завершення треку він щокадру починав грати спочатку, доки маркер був у кадрі.
      • Якщо маркер прибрати й навести знову — сесія скидається, і звук відтворюється знову.
  6. Видалено фіктивні play() / stop() під час завантаження:
      • Очищено обробник завантаження звуків, що запобігає виникненню зайвих клацань та небажаних спрацьовувань Web Audio API під час старту.
